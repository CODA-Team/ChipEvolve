# GoalEvolve platform fork

- Preserve the upstream Teacher, four Students, AST, EPD, objective metrics,
  recipes, bounded retries/repairs and native promotion/rejection rules.
- Released artifact_evaluation/lineage snapshots and historical runs are
  immutable. Prepare common-toolchain professional patches in a private var
  source; regenerate its AST and measure its actual baseline.
- GOALEVOLVE_PLATFORM_PROFILE explicitly enables the platform integration.
  Without it, native API/runtime behavior remains available. Existing Codex
  login is opt-in; never copy or rewrite personal credentials.
- In platform mode all deterministic builds, OpenROAD, official parser and
  checker run through the public EF client in an installed wheel environment.
  Failure must not fall back to an unmanaged native process. Source copying,
  AST and native professional reasoning remain GoalEvolve responsibilities.
- Bind source, compiler/image, binary and frozen design inputs to each run.
  Keep complete original logs and actual failures. Native structural 4/4
  checks do not establish full logical equivalence.
- Cross-project access uses installed public wheels or HTTP only. No sibling
  source imports, sys.path injection, private EF databases or credential logs.
- Runtime state, tool images, builds and experiment outputs belong under var,
  outside the published module. Synthetic unit fixtures are not research
  knowledge or measured experiments.
- Submit only authorized slice files. Publish the platform fork only to
  CODA-Team/ChipEvolve modules/goalevolve; never push upstream origin.
- Slice gates: static checks, meaningful unit tests, file-by-file diff review,
  module-boundary audit and regression. Owner business acceptance is separate.
