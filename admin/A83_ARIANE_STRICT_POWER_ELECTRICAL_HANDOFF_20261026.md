# A83：Ariane/Nangate45 原生功耗回收与定点电气修复

基线根 `ecb3884`。本轮按“具体诊断 → 修复具体阻断 → 针对性短验证 → code-check”推进，未运行新 Teacher/Student 搜索或模型调用，未修改公共产品源码。**得到保持 setup/hold 闭合、GRT 电气违反全零的可继续验证检查点；最终 DRT/RCX、功耗约束与功能资格仍待验证，未采用。**

## 为什么做这一项

A74 最终提取结果 setup/hold 已闭合、DRC 为零，但有 64 个电容违反，功耗 159.392521 mW，超过原上限 159.350917 mW。A78 查清 Nangate45 为单 VT，原 Goal 的纯 VT 回收阶段没有候选；默认 early 回收容许较大时序损失，会破坏本设计已闭合的状态。因此本轮使用原生已有参数：禁止删 buffer、允许最多 10 ps WNS 损失、最多 300 个动作。专业算法、目标、筛选及历史结果保持。

## 具体修复与真实失败

1. 原 Goal `early_forced_reclaim` 完成 300 次 size-down，323 次尝试、23 次拒绝。setup/hold 保持闭合；这一步仍有电气欠账，只保存为中间态。
2. 同进程直接接通用电气修复，触发 RSZ-0074：当前树的负载数量与修改后的网络不一致。该 EF run 保持 failed；已完成 Goal 的 ODB/V 则有注册原件，核对 SHA 后继续使用，没有重算 300 次动作。
3. 新共同 OpenROAD 进程重建工作 GRT 后，原生电气修复可以完成。剩余两个 slew 驱动均由 NAND2_X4 缩为 NAND2_X1；原始 master/native ID 从 DF/DI 核实，当前 master 从该状态的 EF 网表核实。回退这两处缩尺寸。
4. 私有脚本首尝试误用了共同版本不存在的 `size_cell`，执行动作前失败；改为原项目已验证的 `sta::replace_cell`。失败记录保留，无公共兼容层改动。
5. 核查发现首个私有共同物理脚本未显式设置或打印路由层范围。后续显式设置并记录原信号 metal2–metal10、时钟 metal4–metal10，再按实际 GRT 进行电气修复。早期运行没有独立打印范围，不能断言此前用了不同层范围，也不能将同时改变 master 和路由后的差异单独归因于层范围。
6. 正确范围下原生修复将电容违反 13→1，剩余驱动为 `issue_stage_i.i_scoreboard/wire31672`。库中 CLKBUF_X1/X2 最大负载分别为 60.73/121.46 fF，采用原生等价单元替换 X1→X2。
7. 首个单点替换后全量重建 GRT 的候选又出现 13 个电容违反，未通过。修正该局部动作的交付方式：从仅剩一个违反的原父项恢复，先核对全部四项时序及电气计数，再沿 A59 已验证的增量 GRT 方法更新。该分支得到电气全零，原 setup/hold 指标保持。

最后一步表明**保存状态的路由交接方式会影响结果**。两条分支来自同一父项，使用相同的单元升级，最终网表 SHA 均为 `d9e040451574f0969d2c4cfb105be23381668545c0bfee0aa09b2b59a89e6d5e`，分别做全量和增量路由后电容违反为 13 和 0；不能将全量重算当成无影响的文件交付操作。本轮没有更改公共 `qualify` 或原生 ORFS 路径。这不是自主调度优于固定顺序的对照实验。
