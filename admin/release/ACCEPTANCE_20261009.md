## 1. 整理后每个项目到底负责什么

| 项目 | 对使用者提供的能力 | 本轮工程状态 | 本轮能证明的作用和边界 |
|---|---|---|---|
| Execution Foundation | 提交真实任务，查进度、日志、失败、资源、产物，取消并在重启后追溯 | **未通过完整稳定性验收**。成功、真实工具失败、超时和重启追溯通过；默认工作盘的取消时限未过，任务列表出现长超时 | 持久化记录和输入/产物关联可复查；不能宣称取消稳定在 5 秒内，也没有完成相对强直接脚本的全面独立效率证明 |

| Query Agent | 固定问题范围、调查状态、假设与反证、按需证据、补 STA、恢复、停止和交接 | **功能闭环通过，业务质量门槛未过** | Codex 的 D/C 比较有初步增量；相对强直接基线 B 没有胜出。Flash 的关键错误仍需解决 |
| Toolkits | OpenROAD/ORFS 发现、版本、输入加载、命令、工具解析和导出 | **通过本轮开源工具验收** | 实际跑了 Nangate45/GCD 完整流程、定向 STA 和受限缓冲尺寸实验；没有建设商业工具适配 |

源码和开发环境分别位于正式工作区的五个子目录，每个都有独立 Git、虚拟环境和依赖记录。跨项目使用安装 wheel 或公开 HTTP，不依赖其他项目的 editable 源码。Data Interface 没有新增服务和数据库。Query Agent 的主实现来自原独立项目。

Data Foundation 继承了历史解析、关系、fanout、位置/区域、功耗、拥塞和路径增量积累。本轮把原来夹在接口中的设计目录、快照解析、对象匹配与指标归属放回数据层；接口负责传输契约。EDA 命令、库/SDC/SPEF 加载和导出归 Toolkits。现有读取中隐式创建分析的行为改成显式分析操作。Query 工作流已消费这些数据能力，并实际加载四个技能的内容与版本。

Execution Foundation 的运行方式是本机单用户、一个 HTTP/worker 进程，旧账户、会话、控制台和旧计划执行业务没有进入新运行链路。仍保留公共执行契约及其必要内核包；保留一个包名不表示旧用户业务仍在运行。旧目录、用户改动和生产数据库保留原位，不把它们当作新开发源码；没有操作旧 8700 服务的执行、取消或重启。

## 5. Execution Foundation 的稳定性缺口

默认 `/home` 工作盘上，最初 3 次取消到 API 终态分别为 **2.67、8.93、10.11 秒**。独立线程观察原 PID 和进程出生身份，另 3 次全部原进程消失耗时 **5.50、1.75、1.87 秒**，其中一次也超过 5 秒。因此不能把失败解释成仅仅状态查询慢。

重启前后核对了 12 个执行记录，状态、资源、产物和日志完全一致，追溯验收通过。重启前任务列表 API 发生默认超时和 60 秒超时；管理程序只读权威 runtime 数据库确认 18 个任务均已结束，再对准确 PID 和命令执行 SIGTERM，没有触碰其他服务。最初管理脚本误解 SDK 返回类型和过早访问新监听端口的失败也保留。

存储探针显示 `/home` 的小 SQLite 提交明显慢于另一块本地盘。保持同一产品 wheel，在 `/var/tmp` 的独立配置上测试了 3 次真实 OpenROAD/子进程取消，全部原 PID 消失分别为 **0.203、0.606、0.102 秒**，API 收尾亦小于 1 秒。已有 Toolkit 的显式来源客户端按哈希从原实例上传固定输入；第一次直接使用外实例 artifact ID 被拒绝的记录保留。这支持进一步调查存储与同步写入，但实验时刻、状态规模不同，**不是严格配对因果实验，也不撤销默认配置失败**。不得通过只挑快盘成功结果宣称整体稳定性已通过。

EF 的闲时观测约 31 MiB RSS，DF 约 163 MiB；这是重放后的单次进程采样，不是与直接脚本的完整开销对比。取消链路中的同步持久化、心跳和进程停止先后关系，以及列表读取需要专门修复和复测。

## 8. 科研取舍和下一轮优先级

### 平台目标、复杂度与新论文的重合

平台的目标是把确定性、可复用的工作从 LLM 身上移走：统一输入身份和分析条件、完整数据统计、工具启动与停止、产物登记、证据定位、实验比较和任务交接。LLM 负责理解目标、提出解释、判断证据是否充分、选择下一步；平台不能用题号、实例名或某一题的预期结论决定答案。Query Agent 是底座的参考调查应用；其他优化工作流应能使用 EF、DF、DI 与 Toolkits，无需经过 Query Agent。

大批评测文件不能被当作运行时所必需。核查时根仓库未提交的 23 个文件均是 `admin/evaluation` 或 `admin/release`，五个产品仓库未修改。以 H0 保存的提交为起点，Query Agent 的 `src` 目录仍增加了 4,584 行、删除 19 行（含技能资源；其中 Python 源码增加 4,455 行），并增加 1,883 行测试；这是真实复杂度，需要审视，不能用“都是证据记录”掩盖。DF 的 `src` 目录增 491、删 686，DI 源码增 106；EF Python 源码增 48、删 1,620，适配迁移以删除为主。详细边界见 `change-scope-audit-final-v1.json`，不包含 H0 之前整理及 Toolkit 初始迁移。行数不衡量价值；Toolkits 大部分是已有实现的迁移，不能计为新算法。当前大量低层读取、预算结束后没有答案，以及强直接脚本比 Query 更成功，均提示应简化操作和上下文交付，而不是堆题目特例。

用户提供的 [RDF-2026 论文](https://vlsicad.ucsd.edu/Publications/Conferences/434/c434.pdf)与本项目存在实质重合。其第 4 节包含 A2-ORFO 的阶段优化、ReviewDSE 的受保护源码探索、GoalEvolve 的目标驱动演化；4.5、6.1、6.2 也已经涉及版本化设计数据、公共评测基础和 Agent 可复现性。因此“决策 Agent”“数据底座”“固定评测”“保存轨迹”单独都不足以构成独有科研贡献。不能把对方描述成只关注 EDA 工具、不关注基础设施，也不能把黑盒到白盒的路线本身作为本项目创新。

可以验证的差异是把跨工作流公共能力抽出来：不同优化器和 Agent 使用同一事实及证据契约；一次实验在输入、工具、数据、动作、答案和交接之间有可追溯关联；替换模型或工作流时仍能复用并接受相同评测。A2-ORFO、ReviewDSE、GoalEvolve 可作为未来消费者及对照对象，当前没有完成它们三者在本平台上的实际接入，不能宣称已经证明通用性。决策角色先放在调查/编排层，按目标和现状选择查询、补分析或交接，不立即增建新的常驻服务。

记录也有归属：EF 保存任务、进程、资源、输入输出和执行事件；模型 adapter/Agent 层采集请求及实际返回模型标识、提示与技能版本、动作、用量、耗时和公开理由摘要，用共同 ID 与执行记录关联。EF 内核不需要理解 token 或某个模型的推理策略。缺失用量和无法确认的后端版本必须标为未知。保存轨迹支持审计与重放已固定动作，不能保证新 LLM 调用逐字一致；EDA 多线程、数值行为和运行环境也可能带来波动，不能说除了 LLM 外一切天然确定。

下一轮应验证具体收益：同模型、同任务、同预算下，减少定位/解析/拼命令等操作、无效读取和输入条件错误，保持或提高成功率；再用新的设计及另一种工作流验证复用。当前 Codex B 的 16/18 高于 D 的 14/18，尚未证明 Query 比优秀脚本更好。先保留失败和冻结快照，再进行通用接口与流程的简化，不能针对已打开题集补分支或改成绩。

科研地图见 `admin/research/QUERY_AGENT_RESEARCH_AND_PLAN_20261008.md`，本轮选择对应 `admin/evaluation/METHOD_CHOICES.md`：采用 ReAct 的动作反馈循环、按需上下文、明确依赖的查询、持久 checkpoint、领域技能和受限 ECO 反馈；保持现有 Pydantic 和端口体系，没有引入重型编排框架。研究来源的实验成绩没有被当作本项目成绩。

下一轮按真实缺口排序：

1. **先修稳定性和约束执行**：诊断持久化 I/O、取消先后关系及列表路径，在同一状态规模、不同存储、共享负载下配对复测；把只读/改约束权限在公共操作边界落实，不能只依赖提示。
2. **提高调查成功率**：重点改进范围解析、证据发现与预算分配、模型结构化输出恢复、跨实验匹配和补分析后的自动继续。使用新开发案例，不能继续拿这批已观察封存题当未见题调参。
3. **认真追赶强基线**：把 B 的有效索引和工具会话模式纳入下一轮方案比较；保留 B/C/D/E 与全部失败，不用去掉强基线换来宣传优势。
4. **压低关键错误**：特别是 Flash 的条件/单位/输入身份/因果断言，增加答案交付前的确定性检查和反证检查，同时衡量合理拒答与实际推进，避免靠全部拒答提高可靠率。
5. **扩大可移植性证据**：本轮证明同服务器 Python 3.12、x86_64 Linux、Git、Apptainer 及固定开源镜像条件下可安装；尚未证明任意服务器、其他工艺、商业工具或大规模多用户部署。后续再做 OpenROAD/ORFS 多设计和工艺，商业工具适配继续放在独立 Toolkits。

发行候选要等稳定性和 Query 质量门槛通过后再标记。本轮价值是把可复用工程、真实链路和效果边界变成可以检查的东西；哪些部分尚未达到预定要求，也有原始记录可以据此继续工作。
