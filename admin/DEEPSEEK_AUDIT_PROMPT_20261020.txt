二、产品背景和必须理解的分工

项目名 ChipEvolve，是基于 OpenROAD/ORFS 的轻量 AI 集成平台，为 ASP-DAC tutorial 及邀请论文服务。目前只要求老板本机单服务器可用；新用户安装、教学公开演示、远程发布、多租户、分布式、商业化、安全合规体系等不在近期范围。

用户从 Codex 提出目标。Codex 是总控制者和成熟通用 Agent harness：做规划、推理、工具调用、比较、决策和最终评价。我们不从裸模型 API 重新造一个与 Codex 竞争的通用大脑，也不另造“评测底座”。专业项目内部仍可使用原有模型调用和算法循环，这是其专业实现，不要求重写。

平台解决三个工程问题：
- 执行底座 EF：统一实验提交、排队、进程监督、资源预约、运行状态、失败/取消、输入和原始产物登记、执行溯源与可重放信息。
- 数据底座 DF：把 EF 原件解析成带来源的结构化设计事实、快照、摘要、对象/关系、PPA、时序等，供统一查询。大文件和原始产物引用可由 EF 托管，DF 建索引与解释，避免两边各建一套实验真相。
- Query-Agent + DF：让 Codex 高效理解“现在是什么、相对以前变了什么、为什么可能变化、证据是什么”，提供专业交接上下文。Query 是成熟 Codex 的 EDA 垂直工具/上下文/调查能力，不是脱离事实另造因果推理框架。观测差异和因果证明必须区分。

Data Interface（DI）是契约与客户端 SDK，不是第三个后台数据库/服务。Toolkits 负责确定性 EDA/提取工具封装，不承担通用决策。

四个专业能力：
1. Flow Agent：A2-ORFO，黑盒流程配置/参数搜索；保留原研究算法及完整参数含义。
2. DPLEvolve：ReviewDSE 的工程实现，两者是同一个研究项目，不重复计数；优化详细布局相关源码/算法。
3. GoalEvolve：独立源码级优化项目，原 Teacher/Student、AST/EPD、配方、目标距离、评分和晋升机制须保留。
4. TimingECOAgent：ASU-VDA-Lab 的开源时序 ECO 项目，第三方，保留许可证/署名及方法归属。不能删掉来源来声称自己发明 ECO 算法。

希望所有专业的 EDA 动作都进入 EF；设计查询/交接事实经过 DF→DI→Query。原生专业在 EF 托管 session 内读取自己的实时工具报告不等于绕过底座，须区分“专业内部闭环”与“平台跨专业设计事实入口”。避免为了统一而让每条 Tcl 内部读报告都绕一遍 HTTP。

预期数据流：
用户→Codex→Query/DI/DF（理解设计）→选择专业 Agent→EF（实际 EDA/构建/提取）→原始产物→DF（解析事实与证据）→DI/Query→Codex（判断接受/拒绝、继续接力）。
