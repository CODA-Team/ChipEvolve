# 本轮采用的方法与待测取舍

对应科研地图：`admin/research/QUERY_AGENT_RESEARCH_AND_PLAN_20261008.md`。该报告区分读过论文、仓库与文档的证据深度；本文件只记录本轮实现选择，不把文献结果当作本项目效果。

| 来源思路 | 本轮具体选择 | 实际检验 |
|---|---|---|
| ReAct 的推理/行动反馈循环 | 模型提议结构化动作；应用层保存可观察的假设、支持、反证及查询理由，执行后再次决策。 | 真实缺详细路径案例是否取得 STA 并更新结论；D/C 对照。 |
| Context Engineering 的按需上下文 | 按固定 scope 获取有单位、覆盖与来源的小证据包，保留展开入口和完整计数；不丢反证。 | 输入/读取字节、token、来源取回、缺失负例、冷/热开销。 |
| LLMCompiler 的依赖查询思路 | 无依赖读取可走现有公开 batch；身份解析、分析、等待与后续读取按依赖顺序进行。 | batch 不启动 EDA；操作轨迹中的输入身份及结果使用正确。 |
| LangGraph 的 checkpoint 需求 | 本轮遵从批准计划，使用现有 Pydantic 与本地持久化状态，不引入框架。状态端口独立，后续可比较框架实现。 | 真实暂停/恢复后 scope、证据、未完成分析、预算和停止原因保持。 |
| 领域 harness / skills | 四项技能实际加载内容与哈希进入模型输入，不只写版本号。 | 运行轨迹及 no-skills 消融；不得把题目答案写进技能。 |
| TypeSafe JEV 的有界判断 | 只做分层、相关性和支持关系判断，阈值仅用开发集；代码负责事实/权限/预算。 | 100 题、封存混淆矩阵、复杂题错降级、覆盖及整任务效果。 |
| ResizerAgent / ECO 反馈与副作用 | 接收包固定输入、允许缓冲单元和评价条件；真实 Codex 接收者产生新实验，QA 复查 setup/hold/面积。 | 实际接受/拒绝、修改清单、新任务/原生产物；无改善不报告修复成功。 |
| 历史数据层积累 | 继承现有关系、计数、几何、时序增量、功耗与拥塞查询；DF/DI/Toolkit 逐项归位。 | 72 道确定性原生 gold 回归及 B/C 对照，保留准备/维护开销。 |

封存题的成功条件已固定，但新诊断 gold 仍待受控原生命令生成。它不会来自产品解析器的自我打分。效益只按冻结矩阵与门槛报告；架构和测试通过不能代替业务增量证据。
