## CPU 记录实现与范围

`admin/run_native_codex_episode.py` 用 `os.times()` 的前后差值新增 `cpu_usage`，分别保留调用器 user/system、原生进程及其已回收后代的 user/system CPU。测量包含本次调用范围中的输入哈希和结果处理；一次记录进程只承担一个 episode。已回收串行子进程的用量会累加，之前已经结束的子进程不计入本次。

原实现的 `wall_seconds` 已包含输入哈希，`started_at` 却在检查完成后记录。现在时间戳前置到同一计时起点，新增延迟检查确认 `ended_at - started_at` 与墙钟一致；没有改变原截止计算或回写历史记录。

独立 EF/DF 服务与 worker、远端模型计算、未回收或脱离进程树的后代不在该观测范围，不能据此宣称整场 CPU 全部已知。尤其超时清理可能留下未被上级回收的进程用量，仍须保留为未知或另取原始记录。历史回执不补造 CPU 数字；本次没有新增 CPU 硬配额，原生墙钟和 token 口径保持。

`admin/test_native_codex_episode.py` 新增实际串行孙进程 CPU 负荷，核对原生自报的 `process_time/getrusage`、外层累计值和历史进程排除；超时回执也明确保留观测范围。它验证记录器，不能替代真实 EDA 或正式 Codex 对照。
