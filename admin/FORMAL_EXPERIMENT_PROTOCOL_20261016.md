# 正式双核心实验协议草案

本协议是已批准A23–A28长期计划中的冻结前草案。A18 是固定方法接点预检与短查证测试，没有启动本协议的完整专业搜索或统计长轮次。正式开跑前必须生成独立内容冻结清单，填齐设计、原始输入/目标、模型、源码、预算、种子、执行顺序、题集和终止条件；不得把本草案的建议值写成已经执行的实验。

## 两个必须分别证明的业务主张

1. **PPA**：在原时序、电气、布局、DRC 和面积轮廓约束下，专业协同产生最终功耗/面积收益，并与同预算最强单项比较。保留最好分支是交付保底，不能单独当作协同优越性的证据。
2. **平台**：同一 Codex 用统一业务入口更容易正确地完成实验、查询、交接和恢复，减少底层操作与成本；专业能力和最终物理结果不能因此退化。平台提供事实与确定性执行，Codex 保留判断权，不另建评测服务或通用 harness。

## 设计、环境与来源资格

建议首批GCD/AES/JPEG三个真实设计、每设计三个重复，具体轮次待完整预算校准后冻结。GCD/AES是工程开发样本；JPEG已经参与A24兼容和完整专业预演，也必须标为开发/校准样本，不能再称未见设计。新key和独立上下文只证明新运行，不能恢复设计的未见资格。首批结果只支持这些设计和冻结环境下的收益/复现结论；独立未见设计和更广论文统计另冻结，不为凑数量重新纳入已排除的来源。**A19已使JPEG显式完整旋钮来源通过复制/环境资格，A24正在运行完整专业预演；picorv32来源复制PPA不一致，仍被排除。** JPEG来源资格与JPEG完整专业优化/交接通过分别验收，不能把前者记成后者。

支持范围先固定为已验证 ASAP7、单物理时钟。固定基础 ORFS `5105b0a77`、OpenROAD `27288f5c90`、镜像 sha、工具/脚本/Make 展开参数、库/SDC、时钟单位、功耗活动假设及最终 FF 提取条件。Code 的共同基础加原研究增量和私有候选构建保留；不能用 stock binary 替代研究算法。

原 ORFS、现代完整来源和专业优化结果分列。AES 现代来源违反原功耗/面积/轮廓条件，仍可作为探索/负例，但不默认送给不能改变轮廓的下游，更不成为正式采用结果。允许 Codex 明确选择同修订、同目标/条件且已验证的原 ORFS 或既有分支；所有方法共享同一允许来源政策，不能给团队额外的历史最好结果而不给单项。

每个输入绑定 RTL 修订及完整功能证明，不能把同名 design 或实验名当成相同输入。物理设计阶段转换、清线/重布线和必要补算写入方法条件。最终七项 PPA 之外同时记录电气、布局和 DRC。

## 实验一：PPA 与协同

| 对照 | 要回答的问题 |
|---|---|
| ORFS 默认 | 相对传统流程的产品收益 |
| 完整来源，不调参 | 来源/综合路线改变本身带来多少差异 |
| Flow、DPL、Goal、适用 ECO 各单项 | 相同来源政策与总预算下各专业能力 |
| Codex 选择分支与接力 | 团队是否优于最强单项，是否发生正向接力 |
| 固定 A、B、A→B 及移除一项 | 收益是否被接力保留；边际贡献与冲突在哪里 |

固定方法表与新搜索表分开。每专业内部原评分、原目标与筛选规则保持，统一最终事实供 Codex 决定；不把局部 HPWL 或原生功耗代理变好视作最终 PPA 改善。不强制固定四专业顺序，允许并行分支、跳过无适用 ECO 和保留早期合法分支。

此前草案建议每设计/重复/优化方法8小时墙钟、100万模型输入+输出token、64核时CPU，均未冻结。A24真实JPEG一轮Goal的Teacher/四Student在EDA评价完成前已记录6,048,023个输入+输出token，另有Query和其他专业成本，证明100万不足；不得据此减少原生Student或参数域。最终预算待完整轮次、交付及验证校准后统一冻结。团队在相同**总量**内分配，不能每专业再各领一份。共享源码冷构建、每候选编译、EDA、Query、Teacher/Student/review、恢复成本均入账；机器资源与并发按共同规则分配，不在正式输赢出现后单独加时。

建议种子固定为 `11, 29, 47`，所有方法按相同种子组执行；模型后端不提供种子时记录为不支持，保留重复编号而不虚称确定性。执行顺序在开跑前随机冻结、各侧独立上下文；实际调度/并发和缓存状态完整记录。

A24记录到的原生配置为Flow `gpt-5.6-sol/low`、Goal `gpt-6.1-sol/xhigh`；DPL本轮未传显式模型参数、使用当前Codex默认值，属于预演来源限制。正式冻结时使用原生已有模型/推理参数显式固定，单项与团队中同一专业保持相同配置；通用Codex直接/平台两侧必须完全同模型/推理设置。分别报告各模型token及缓存子集，不把不同专业原生配置冒称统一模型对照。

A24多专业同时共享32核/128GiB，已经出现实际资源等待、链接配额失败和原生评价超时。校准分别记录排队、原生计算、编译、数据和恢复，不把争用墙钟当作方法固有耗时。正式计时试次按冻结顺序逐组运行，组外EDA、全仓回归和额外索引准备不与其并行；组内原专业并发/串行规则保持。属于业务任务本身的数据导入/索引仍计入该侧成本，冷准备与热态复用各自报告，不能将平台开销挪到计时区间外。

主表报告原约束可行率、最终功耗/单元面积/core/die、setup/hold TNS 与 slack、失败/未完成及成本。主目标是原时序约束内最小功耗、兼顾面积；slack 是余量，不能不重新冻结周期并重跑就宣称更高频率。功耗来自相同活动假设下工具估计，不能当硅实测。

团队交付不差于单项与团队带来正向接力是两层结论：只有“保留最好”时写保底成功；额外收益须与相同预算最强单项比较，并报告全部设计和重复，不能只选择 GCD 成功例。逐设计给差值与分布，小样本不报统计显著。

## 实验二：统一、集成与封装

同一 Codex/模型/推理设置/预算；直接侧拥有相同原项目、算法、工具及可执行权限，平台侧用本机封装入口。两侧均可使用原生 Codex 工具和脚本，不能限制直接侧来制造优势。

| 场景 | 正确完成条件 |
|---|---|
| 发起并监控完整真实实验 | 输入、目标、终态与最终产物身份正确；任务被消费，异常可解释 |
| 查询某设计实验/产物 | 全目标集合完整、引用可查，不混入参考项或其他设计 |
| 比较、诊断和下一步 | 全部原约束正确，事实与假设分开；归因有输入/阶段证据，必要时验证假设 |
| 选择专业并实际接力 | 来源和阶段被真正消费，最终结果可查且无未解释覆盖 |
| 交付中断、取消和恢复 | 同任务身份重接，已成功物理计算不重复，失败与恢复成本保留 |
| 验证并保留结果 | 完整输出证明、独立物理重放、SDK 一致，差分支不覆盖合法结果 |

预先冻结任务文本、**精确目标 run 集合**、约束含义、证据规则及独立 oracle；reference、source、candidate、retained 各自角色明确。答案核查不调用平台自己的 winner 逻辑代替独立真值。事实查询、因果诊断和真实操作分别计分。

主指标是全尝试正确完成率、引用/事实正确率、身份与最终 PPA 一致性、人工干预/路径修补、业务工具调用、重复 EDA；成本统计全部模型输入/输出和缓存、工具/CPU、墙钟、队列、数据读取与恢复。cached input 是 input 子集，不重复相加；缺用量为未知，不能记零。

同时列出全尝试成功率与“双方正确且用量完整”的成对成本和配对数。失败成本单列并纳入全尝试总量；错误答案更快不能成为效率收益。原始/规范化结构化 JSON 与平台紧凑事实属于较窄的候选查证对照；它不能代替完整实验提交/监控/交接的封装实测。

冷启动的安装、索引、导入与准备成本和热态复用分别报告；公共历史索引的建设成本不能隐藏。A18 的三次/设计只读重复，至多支持该候选查证任务的描述性观察；后续使用未看过题集做正式端到端验证。

`a25-model-bindings-prepared-20261017.json`记录当前源码及非凭据配置的SHA。Query的现有宿主显式使用`gpt-6.1-sol/medium`；Flow生成器和critic为`gpt-5.6-sol/low`；Goal的Teacher和四Student配置为`gpt-6.1-sol/xhigh`；原生ECO传输缺省为`gpt-6.1-sol/high`，模型名可由既有环境项覆盖。正式清单须记录实际设置，直接/平台的同一Codex角色必须匹配，专业单项/团队中的同一专业也必须匹配；不把不同角色使用不同原生模型误报为同模型对照。

## 开跑门槛与交付

- 所有正式设计通过来源复制一致、版本语义和输入/库/目标资格；第三设计失败时不靠减少原能力或放宽约束充数。
- 当前设计准备、原任务恢复与 EF→DF 查询无未解释失败；所选结果完整证明和重放通过。
- 任务集合与基线/候选角色无歧义，两个 Code 新搜索预算能覆盖原生最小轮次，专业实际消费 Query 上下文。
- 每个方法有不可变清单、所有尝试账本和终止条件；先审批冻结，再运行长轮次。未知模型用量、预算耗尽和专业无适用动作各自保留。

交付按设计可追溯的原始结果、匹配对照、采用/拒绝理由、全部失败与成本、完整验证引用和两个业务主张各自的支持程度。正式结果不预设必须正向，不在结果出来后换基准、删失败或改成功标准。
