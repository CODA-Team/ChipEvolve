# 四层底座的工程验收

本轮目标是四个可独立安装、独立测试的工程项目。主 Query Agent 来自独立仓库；Data Interface 是 SDK，不运行后台服务。默认闭环用本机 OpenROAD，无 Web 产品。

| 项目 | 拥有的职责 | 不应拥有 | 验收与 Codex 对照问题 |
|---|---|---|---|
| Execution Foundation | 单机任务生命周期、隔离目录、日志、取消、资源记录、不可变产物与追溯 | 账号系统、旧控制台、上层搜索推理 | 进程失败/取消/重启后，实验记录是否完整；一次短工具调用是否反而增加成本 |
| Data Foundation | 不可变快照、实验关联、对象解析、作用域、规范化指标与证据 | AI 回答、SDK 传输 | 多 run/stage 与同名对象是否误配；导入成本与重复查询收益 |
| Data Interface | HTTP 编码、稳定契约、SDK、Agent 工具定义 | 数据目录聚合、匹配判断、分页后的业务过滤 | 调用/输出体积、接口错误；简单 curl 是否同样有效 |
| Query Agent | 问题规划、比较、证据组织、缺数据说明 | 原始文件管理、工具执行、复制数据服务 | 答案正确性、引用、歧义拒答与根因过度推断 |

实施顺序：权威数据入口 → 薄 SDK → 实际数据适配器 → 轻量执行服务 → 独立 wheel 闭环 → 对照试验与改进。

对照要求：相同模型、相同输入与任务；直接终端组可写脚本，infra 组记录准备/索引成本；保存 codex exec JSON 事件与最终答案。机制测试、合成数据实验和真实 EDA 试验分别标注。少量样本只报告观察，不推断总体优势。未执行或失败的试验不得写成通过。

生产基线仍在旧目录。代码精简在新工作区进行，不能删除生产数据或未核查的进程。每个仓库保留独立 Git 历史和环境。
