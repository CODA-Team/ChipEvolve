# A30：允许显式选择 ECO 原生布线校准策略

2026-10-22，本轮八组实验仍未全部验收。此项是后续实验的接入修正，不是新增 PPA 结果。

## 实际问题与业务影响

平台此前在 `chip_evolve/native.py` 固定设置 `DRT_EVERY_ITER=1`。TimingECOAgent 本身支持快速 GRT 探索与周期详细布线校准，原生默认是关闭每轮 DRT，当前原生周期为八轮。平台将一种运行策略写死，使大设计无法直接选择原项目已有的另一种策略。

当前 Ariane/ASAP7 会话 `run-b73f5c911f0b413bae04cbc1d5f3e138` 的第一轮确实执行全设计详细布线，观察到约 23 GiB 进程内存占用。会话预约 32 GiB，其他测量、修复与证明任务因此等待。这是实际计算与调度成本，不是任务丢失。

## 本次修改

- `chip_evolve/native.py`：读取已有专业模块配置块内的 `professional.eco.drt_every_iter`；未配置或为 `true` 时仍传入 `DRT_EVERY_ITER=1`，显式为 `false` 时传入 `0`。
- `admin/test_eco_pdk_binding.py`：覆盖默认、显式开启、显式关闭三种模式与两种资源配置，检查冻结 profile 实际收到的环境值，并继续检查输入、工艺和线程绑定。

示例为后续独立实验的配置，不应用到正在运行的 profile：

```json
{
  "professional": {
    "eco": {
      "drt_every_iter": false
    }
  }
}
```

原 ECO 动作、上下文、评分、回退和周期校准实现均由原项目继续负责。函数签名、EF/DF/DI 接口、服务容量、最终物理交付与采用约束均不变。周期模式的中间 GRT 估计不能作为最终 PPA；最终仍需完整详细布线、寄生提取、DF 事实与相应功能验证。
