## 已证实的问题和改动

1. **执行底座仍有一条文件托管路径占住公共锁。** 普通产物路径在 A6 修过，但运行 ZIP bundle 的文件/字节托管仍在连接锁内。两项回归在修复前失败；移出耗时文件操作后，心跳可并发进行，元数据注册仍原子化，四项 bundle 回归通过。保留内容校验、产物身份、失败证据和 first-writer 行为。
2. **worker 状态有过密持久化写入。** 每 50ms 轮询都做 SQLite UPSERT，运行线程在 SQL 内持有公共锁，心跳/health 在同一锁等待，真实栈重复捕获。相同 worker 状态改为每秒最多一次；PID、首个运行任务或状态变化仍立即记录。回归修复前实测多出19次写入，修复后通过；采样时间放到锁内。没有延长 lease、关闭持久化或改变失联规则。此修复减少写入，但不足以解决当前磁盘延迟。
3. **数据交付首次读超时会进入永远等不到回执的分支。** 若最初 GET `/imports/{artifact}` 超时，旧代码直接进入对账；即使后续确认404也不会提交 POST，最终 `import_outcome_unknown`。新代码区分本次是否已经发送 POST：恢复读查询并确认无回执后才提交；已发请求只对账，不盲目重发。首次读故障恢复、持续故障不盲提交、响应丢失、身份/实际失败等23项测试通过。

这三项都不改变专业算法、设计名适配、公共函数签名、HTTP/SDK、数据库结构或原业务取舍。没有引入新服务、调度器、评测底座或通用 Agent harness。
