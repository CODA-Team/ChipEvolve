2026-10-10，用户确认 P0 分阶段规划并授权开始执行。当前主线是 Codex 驱动的 Query 与 Flow 真实优化闭环，正式工作区为 `/home/wjyuan/projects/eda-development`，Flow 使用本机已验证的 `yfz2024/A2-ORFO` DRP 版本。

Codex 负责目标、判断和调度；基础设施承担确定性的执行、数据整理、产物溯源与恢复。保留专业项目算法与独立环境，使用 wheel 或 HTTP 连接现有模块。Data Interface 保持 SDK。

## 施工顺序与业务验收

| 阶段 | 用户得到的能力 | 验收要求 |
|---|---|---|
| P1 | 真实专业优化器的可复建基线 | 同一实验完成真实模型决策、两轮三候选、预测排序、阶段替换、参数实际被物理工具消费、完整物理设计及正常结束。 |
| P2 | 可统一管理的阶段执行 | 真实阶段由执行底座管理；取消、实验列表和指定产物导入通过验收。 |
| P3 | 可查询和续跑的优化实验 | 真实评价回流；中断后继续同一实验，完成阶段不重复执行。 |
| P4 | 第一条自主业务闭环 | Codex 查询、优化、读取反馈并停止，预算内无需人工搬运和交接。 |
| P5 | 新设计复用与源码优化 | 扩展设计，并分别接入 DPLEvolve 与 GoalEvolve 的真实源码演化。 |
| P6 | 可交付的平台与可信效果证据 | 干净安装、重放、公平对照、Tutorial 与论文材料。 |

ReviewDSE 与 DPLEvolve 是同一项目；GoalEvolve 独立。ECO、API 主导的通用编排服务、多用户系统和前端暂缓。

优化收益以固定评价条件下的可行结果为准。成功执行不等于改善，超功耗的时序改善不计收益。不得把多次不完整实验拼成一次完整验收。

## 首次实验预算

Nangate45/AES，seed 42，两轮，每轮三个候选，elitist 每阶段替换一个候选，保留 `-A -P`，不使用 `-N`。物理并发为一，每候选两个线程；阶段批处理时限先设 20 分钟，整个实验最多三小时。模型使用封存配置及官方 Codex transport。超过预算或遇到确定性失败，保存原因并修复后另开实验，不修改正在执行的源码。

首次实验已退出 1：串行布线的整批 20 分钟只够基准候选完成，最终关卡为 1/3 有效、低于最低 2。完整重试仍限制三小时，改为每候选八线程与整批阶段 90 分钟；算法、两轮三候选、物理并发一、真实模型及功耗条件保持一致。这是根据实际耗时调整运行预算，不是放宽原生验收或减少流程。
