# 邀请论文近期交付：GCD 先收口，再扩三设计

本计划落实老板 2026-10-20 的最新要求。10 月 30 日论文截止，约 10 月 23 日向老师交稿，实验集中在接下来的两三天。它覆盖旧 `FORMAL_EXPERIMENT_PROTOCOL_20261016.md` 中近期不再必做的评测规模与前置要求；不改写既有实验记录，也不改变模块公共契约。

## 老板最终拿到什么

1. GCD 一条有实际增量的协同优化主线：每棒做什么、指标怎么变、为什么接受或拒绝，输入输出能追溯。
2. ibex、jpeg、ariane 三个设计的真实可运行性与案例结果，完整标注成功、失败或尚缺环节。
3. 一张平台业务图和一份按设计追踪实验/产物/诊断的记录，说明 Codex 如何把确定性工作交给 EF/DF。
4. 可直接进入论文的指标表、追踪图、方法条件和适用范围。平台效率只报告实测范围，不编造节约比例。

## 近期验收口径

不要求 baseline 与 Agent 同时运行，不要求相同团队总预算，不要求全部单项、消融、三次重复、54 个配对 episode 或完整 benchmark 先完成。已有好结果可复用，条件/来源/时点明确即可。

仍核对设计修订、约束、单位、阶段、工具/库、完整 PPA 与最终采用产物的功能证据。每棒实际参与、未执行、未采用必须可区分。某棒无收益可保留父状态；不能把不同分支拼成实际不存在的连续四棒，不能把来源改变带来的全部收益算作某个 Agent 的增量。

## 执行顺序与业务交付

| 顺序 / 目标窗口 | 业务交付与验收 | 涉及范围 | 停止扩张的条件 |
|---|---|---|---|
| P0，10/20 | 交付 DeepSeek 独立审查提示词；从已有原件导出 GCD 完整指标和真实祖先关系；列出已修复/候选/未修复 | 本轮只读证据与文档 | 不等待正在运行的 JPEG 才交付；不新增证明/搜索 |
| P1，10/20–21 优先 | 收口会破坏新实验真实性的最小修复：Goal 已验证归档器补丁成为明确默认来源；按设计目标配置原生子目标；区分已 DRT 完成结果的测量与重布线；ECO 工具线程与预约一致 | Goal、根 native/delivery/physical、ECO 工具入口；先按实际调用确定最小文件，不改变研究评分/公共接口 | 复用已有回归；每个问题一次针对验证。若当前 GCD 主线不经过该缺陷，修复不阻塞已有结果整理 |
| P2，10/21 优先 | 收口 GCD 实际主线。先复用 Flow→Query→Goal 的合法结果；为 DPL/ECO 确定适用阶段与真实父状态，再按诊断做必要接力。新增、拒绝、跳过分别记录 | 既有业务 CLI、EF、DF/DI/Query、专业配置 | 无必要动作不强行修到坏；同配置无新证据不重复长跑。四专业的展示不能伪造；实际缺棒明确标出 |

以上是工作优先级与目标窗口，不是声称这些阶段已全部完成，也不是每个设计都保证有正收益。若一个设计在窗口内达不到条件，报告失败原因和已完成证据，不填补“漂亮结果”。

## 每棒必须留下的事实

`design/revision → parent → Agent/strategy → EF run → output artifacts → DF snapshots → Query evidence → Codex decision`。

每个实际完成节点包括功耗、cell/core/die 面积、setup/hold WNS/TNS、电气违反、route DRC、阶段/角/单位/约束、产物和来源、验证状态。成本有多少记多少，unknown 不填 0。拒绝或未运行没有自己的 PPA 时，不能复制父指标冒充该 Agent 的结果。
