# Repo Context Audit - 2026-04-25

This audit is for agent context control.  It does not delete anything; it
classifies which directories should be read by default and which directories
can slow or bias future base-family work.

## Default Context

Use these first for base-family algorithm work:

- `AGENTS.md`
- `family_robustness/BASE_FAMILY_STATUS_20260425.md`
- `family_robustness/ROBUST_BASE_DECISION_20260425.md`
- `knowledge/algorithm_cards/base_family_cards.yaml`
- `knowledge/algorithm_cards/algobank50_findings_20260425.yaml` only as
  evidence, not as an implementation startpoint
- the active family robustness directory

Use runtime artifacts only when a named gate or failure signature needs to be
verified.

Treat these as the only default base-family algorithm targets until newer
evidence supersedes them:

- `negotiation_row_bucket_quality_frontier_r5`: best current robust candidate;
  improves AES and JPEG HPWL/runtime in same-run gates, but still needs BP/large
  promotion before paper-scale claims.
- `netaware12_prefilter_hotset_guard`: quality-repair candidate; AES/JPEG/ARIANE
  legal with HPWL gains but runtime overhead remains meaningful.
- `legalm_counterfix_r4`: structural LEGALM repair evidence; useful as an
  evolvable direction, not a quality parent yet.
- `legalm_stage1_quality_guard_r5`: legality/quality guard experiment; keep as
  evidence only until JPEG/BP quality is acceptable.

Do not spend default worker time on:

- broad algobank mixtures;
- fallback-to-diamond/default variants;
- localized swap as an initial parent;
- priority escape unless a real stuck/no-valid-candidate failure is present;
- small-case-only tuning.

## Cleanup Notes

- `.dpl_evolve_state/` is ignored in `.gitignore` and is the preferred active
  runtime root when `DPL_EVOLVE_STATE_ROOT` is unset.
- `family_ideas/` and `variant_ideas/` are now local-only archives; promote
  only distilled, evidence-backed content into `knowledge/algorithm_cards/`.
- Worker reports must be written under
  `dpl_evolve_agent/family_robustness/<family>/`.  If a worker writes outside
  this repo root, that is a boundary miss; move the report back into this repo
  and remove the stray directory.
- If a physical cleanup is needed, remove only generated bytecode and local
  runtime artifacts after confirming no active worker is using them.
- Do not delete `family_ideas/` or `variant_ideas/` without an archive decision;
  they may still be useful for future ideation, but they should not be default
  agent context.
