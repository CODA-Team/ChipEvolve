# Agent Context Hygiene (2026-04-25)

This note is for future agents entering `dpl_evolve_agent`. It records the
current context map and the directories that should not be broad-read by
default. No files or directories were deleted during this audit.

Scope of the audit:

- Root: `$DPL_EVOLVE_AGENT_ROOT`
- Depth: top level plus two directory levels below it
- Excluded from content reading: `.git` internals
- Write boundary: do not edit tracked files in the configured ORFS checkout or
  its `tools/OpenROAD` submodule from family-evolution work. The ORFS tree is
  still the interaction workspace, while generated variants, private builds,
  evaluator outputs, and metrics should live under `DPL_EVOLVE_STATE_ROOT`.

## ORFS Interaction Boundary

Use ORFS as the place where the flow is exercised. A family worker may:

- read ORFS snapshots, reports, and installed/core build products;
- write generated variant source, private build directories, private binaries,
  and evaluator artifacts under `DPL_EVOLVE_STATE_ROOT`;
- run the strict evaluator from the same ORFS handoff snapshots.

A family worker must not:

- edit tracked ORFS flow files, design configs, Makefiles, or scripts as part
  of algorithm evolution;
- edit the checked-out `tools/OpenROAD` submodule directly as the durable
  implementation;
- treat runtime-generated variant source as the final source of truth.

If a generated variant works, the durable change must be copied back into
`dpl_evolve_agent` as a generator change, family patch, algorithm card, router
rule, or robustness note.

## Do Not Broad-Read

Treat these as context-pollution or archive surfaces unless a task explicitly
asks for them:

- `.git/`: repository database, not agent context
- `__pycache__/` and all nested `__pycache__/`: generated Python bytecode
- `tasks/archive/`: historical bootstrap prompts
- `variant_ideas/`: older idea prompts, not promoted base-family cards
- `family_ideas/`: exploration idea bank, not robust-base evidence during the
  current hardening phase
- `knowledge/reference/OpenDP.pdf`: background reference only
- `knowledge/reference/commands.txt`: command scratch/reference only
- `knowledge/replay_bank/*.md`: long replay notes; use the compact registry or
  family cards first
- `DPL_EVOLVE_STATE_ROOT/experiments/*`: runtime evidence; read only when a
  gate artifact is named

Small-case smoke evidence is not a base-family success. `aes` and other small
cases catch build, legality, and obvious regressions. A base family is not
promoted until its mechanism is understood on medium and large stress cases
such as `jpeg`, `ariane133`, and `bp_quad`, or until the remaining gate
failure is explicitly documented as evaluator/runtime infrastructure rather
than algorithm quality.

## Agent Rule Of Thumb

Start from compact, durable cards. Use runtime artifacts only to verify a
specific gate or failure. Do not turn smoke JSON, replay logs, or archive
prompts into the next agent's default context.

For the current base-family hardening phase, do not start from algobank
mixtures or idea-bank variants.  Use them only as evidence to isolate a
mechanism, then harden that mechanism in a clean family implementation.
