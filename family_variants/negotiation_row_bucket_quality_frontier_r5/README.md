# negotiation_row_bucket_quality_frontier_r5

This is the current flow-ready row-bucket negotiation candidate.

Use it through `run_variant_experiment_matrix.py` rather than by editing ORFS
or OpenROAD directly:

```bash
python3 scripts/run_variant_experiment_matrix.py \
  --experiment-id row_bucket_r5_gate \
  --variants negotiation_row_bucket_quality_frontier_r5 \
  --cases aes_nangate45 jpeg_nangate45 ariane133_nangate45
```

The variant keeps the normal `detailed_placement_evolve -use_negotiation`
entrypoint.  Its family behavior is generated by the matrix script:

- row-bucket active-set construction;
- dirty-region bystander repair;
- capped large-design candidate generation;
- no diamond fallback as family success evidence;
- net-anchor quality scoring on a bounded cheap-score frontier.

Current evidence is promising but not final.  AES and JPEG strict gates improved
HPWL and runtime versus same-run baselines.  The next promotion gate must be a
large/stress case such as `ariane133_nangate45` or `bp_quad_nangate45`.
